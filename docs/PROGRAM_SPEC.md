## 2. 핵심 원칙
1. **완전 오프라인**: 앱은 `127.0.0.1` 로컬 서버에서 실행하고 외부 요청을 금지한다. 모든 에셋은 로컬에 둔다.
2. **입력 최소화**: 방문객 입력은 **사건 버튼 4개 + START 1개** 가 전부. 터치 없음.
3. **콘텐츠와 엔진 분리**: 사례가 바뀌어도 셸 코드를 고치지 않는다. **사례 = JSON 1개 + 에셋 폴더 → 렌더 → MP4 + 메타데이터**.
4. **무음 이해**: 소리가 없어도 자막과 화면만으로 100% 이해된다.
5. **실패해도 보기 좋게**: 어떤 오류가 나도 검은 화면이나 브라우저 오류창을 띄우지 않는다. 최후 수단은 정적 로컬 루프(SAFE_ATTRACT).

## 3. 런타임 아키텍처 — 하이브리드 (합의)

```
 [Case JSON + assets] ──(build)──▶ [Validator] ──▶ [Render: 같은 HTML 엔진을 헤드리스로 녹화] ──▶ case-00N.mp4 + meta.json + hash
                                                                                                        │
 [Arcade buttons] ─USB 인코더(키보드)─▶ [Station 셸 (HTML/JS, Chromium kiosk, 127.0.0.1)] ◀──────────────┘
                                          IDLE / ARMED / PLAYING(MP4 재생) / OUTRO / 복구
```

- **현장 런타임은 검증된 MP4만 재생** 한다 → GPU·폰트·브라우저 버전 리스크 제거.
- **본편은 손으로 편집한 영상이 아니라, 사례 JSON을 읽는 HTML 애니메이션 엔진을 헤드리스 Chromium으로 녹화해 생성** 한다 → 사례 문구 수정 시 JSON만 고치고 재렌더(수 분). 데이터 기반의 장점(수정 용이성, 스키마 검증)을 유지한다.
- 엔진이 실패하면 모션 디자이너가 같은 레이아웃으로 수작업 편집한 MP4로 대체할 수 있다(셸은 MP4만 알면 됨).

| 항목 | 사양 |
|---|---|

| PC | Station당 미니 PC 1대 + 동일 이미지 예비 1대 |
| 입력 | USB 아케이드 인코더 → 키보드 입력 매핑 (`1`~`4` = 사건, `Space` = START). **USB 장치 경로 고정** |

| 부팅 | BIOS "정전 후 자동 전원 ON" → OS 자동 로그인 → 셸 자동 실행. 사람 개입 0 |
| OS 하드닝 | 절전·화면보호기·알림·자동 업데이트(재부팅 포함) 비활성, 로그 순환·디스크 상한 설정 |

## 5. 화면 상태 머신 (Station)

```
 [BOOT] ─▶ [SELF_TEST] ─ok─▶ [IDLE] ─(1~4)─▶ [ARMED] ─(START)─▶ [PLAYING] ─(end)─▶ [OUTRO] ─(10s)─▶ [IDLE]
               │fail                ▲  (START: spotlight 사례) │15s 무입력   │error/stall
               ▼                    └───────────────────────────┘           ▼
         [SAFE_ATTRACT] ◀── 60초 내 크래시 3회 ─────────────────────────── [IDLE] (+미완료 기록)
```

| 상태 | 화면 | 입력 처리 |
|---|---|---|
| BOOT / SELF_TEST | 부팅 화면 | 콘텐츠 해시, MP4 4편 디코딩, 입력 장치, 저장공간 확인. 실패 시 SAFE_ATTRACT + 운영자 경고 |
| IDLE | 사건 폴더 4개가 **8초 간격으로 차례로 스포트라이트**, "SELECT CASE → PRESS START" | `1`~`4` → ARMED. **START만 누르면 지금 스포트라이트된 사례를 재생** (13절 합의 ②) |
| ARMED | 선택한 사건 표지, START 안내 점멸 | 다른 숫자 → 사건 변경. START → PLAYING. 15초 무입력 → IDLE |
| PLAYING | 사례 MP4 재생 + 셸 오버레이(진행 바) | 방문객 입력 **폐기** (해제될 때까지). 영상 정지·디코딩 오류 5초 → IDLE + 미완료 기록 |
| OUTRO | "MISSION COMPLETE · 자리로 돌아가 같은 지시를 Copilot에 입력해 보세요" | 10초 후 IDLE. 입력은 키 해제 이후부터 다음 상태에서 인정 |
| SAFE_ATTRACT | 정적 로컬 루프 영상 | 방문객 입력 무시. 운영 패널로만 복귀 |

### 5-1. 입력 규칙 (물리 버튼)
- 모든 버튼은 **80ms 디바운스 후 눌림 에지 1회만 인정** 하고, 다음 입력은 안정적인 키 해제 후 허용한다. OS 키 반복(keydown repeat)은 무시한다.
- **2초 이상 고착된 입력은 `FAULT_INPUT`** 으로 기록하고 해제 전까지 무시한다. 고착된 START가 IDLE 복귀 직후 재시작을 유발하지 않는다.
- 동시 사건 입력은 **가장 먼저 확정된 1건만** 채택한다.
- START 장기 입력은 어떤 운영 기능과도 연결하지 않는다.

### 5-2. 복구 규칙
- 비정상 종료된 세션은 **이어서 재생하지 않고** 미완료로 기록한 뒤 IDLE로 복귀한다.
- watchdog: 셸 크래시 시 5초 안에 재실행. **60초 내 3회 크래시 → SAFE_ATTRACT** + 운영자 경고.
- 상태·카운터 파일은 **원자적으로 저장**(임시 파일 쓰기 → rename)한다.

### 7-1. 비개발자 입력 · 검증 절차
- 콘텐츠 담당자는 **스프레드시트 입력 템플릿** 을 채우고, 변환 스크립트가 JSON을 만든다 (JSON을 직접 편집하지 않음).
- **Validator (Must)** 는 다음을 검사하고, 오류가 있는 사례는 렌더·배포를 차단한다.
  - JSON Schema(`schemaVersion`) 필수 필드 · 타입
  - 모든 노출 문자열의 ko/en 존재
  - 에셋 파일 존재 여부, 이미지 해상도 하한
  - ID 참조 무결성 (`fromEvidenceId`, `targetAnchorId`)
  - 타임라인 단조 증가, 마지막 단계 종료 = `durationSec`
  - 효과 수치의 근거 필드, 인용문 `consentConfirmed`
- **미리보기 (Should)**: 브라우저에서 JSON을 끌어다 놓으면 엔진이 바로 재생해 렌더 전에 확인한다.

## 8. 미러 · 카운터

### 8-1. 미러 (Should)
- MVP는 **미러 PC가 독립 플레이리스트** (Attract 루프 + 4개 사례 하이라이트)를 재생한다. Station과 네트워크로 연결하지 않는다.
- HDMI 분배는 "고정된 한 Station만 확대"해도 되는 경우에만 선택한다.
- 실시간 동기화(세션 스냅샷·heartbeat·seek)는 **Won't (MVP 제외)**. 필요해지면 `{stationId, sessionId, seq, state, caseId, contentVersion, startedAt}` 이벤트 + 2초 heartbeat + 접속 시 스냅샷 + 500ms 이상 차이 시 seek 방식으로 확장한다.

### 8-2. 완료 카운터 (Should)
- 표시명은 **"기밀 해제 완료"**. OUTRO에 정상 도달했을 때 `sessionId`당 한 번만 +1, 원자적으로 저장한다.
- 시작 횟수는 KPI용 `playStarted` 로그 지표로 따로 남긴다.
- MVP에서는 Station별 로컬 카운터를 두고, 합산 표시는 운영 패널의 수동 입력 또는 행사 후 로그 합산으로 대체한다.
- 의뢰서 투입은 Station과 묶지 않는다. MVP에서는 스태프가 수기로 집계한다.

## 11. 설치 · 철수 런북 (필수 산출물)

## 12. MVP 범위 (6~8주)

| 등급 | 항목 |
|---|---|
| **Must** | 하이브리드 Station 셸, 4건 × 90초 본편, 입력 안전 처리, 자동 부팅·watchdog·SAFE_ATTRACT, 오프라인 동작, Validator, 실제 장비 10시간·전원 복구 시험, 설치·철수 런북 |

## 14. v0.3 변경: 미션 카드형 3건 (시안 반영)

- 실제 사례 3건으로 확정하고, 방문객이 **미션 카드 1장을 뽑으면** 해당 미션을 끝까지 자동 재생하는 구조로 바꾼다.

| 미션 | 부서 | 지령 | 시작 화면 | 결과물 |
|---|---|---|---|---|
| 01 · AGENT GOLD | 투자운영파트 | 초기 스타트업 투자 심사역으로 위장 잠입, 1차 투자검토 수행 | IR·재무제표·시장 리포트가 뒤섞인 자료 화면 | 출처가 달린 1차 투자검토 메모 |
| 02 · AGENT BLUE | 글로벌U/W기획 | 영국 이동 지령, 20분 안에 출장 품의 상신 | 빈 해외출장 품의서 + 20분 카운트다운 | 일정·경비가 채워진 품의서 |
| 03 · AGENT RED | 기획파트 | 글로벌 OO보험사 실적 정보 확보 | 해외 보험사 IR 홈페이지 | 출처가 달린 실적 비교 브리핑 |

- 재생 단계 (약 85초): 미션 수령 → 문제 상황 → **+Secret Agent 호출**(데이터 첨부·프롬프트 공개) → 데이터 처리(근거 위치 표시) → 결과물 생성 → 사람 검토(빨간 펜) → 사례 공개(CASE FILE) → 종료
- 화면은 **16:9 가로** 로 변경한다. 실제 업무 화면 옆에 Agent 패널이 열리는 구성이 가로에서 자연스럽기 때문이다 (5절의 세로 레이아웃 대체).
- 입력: 미션 카드 버튼 3개 (또는 카드 RFID 태그). 카드를 뽑는 동작 자체가 START다.
- 시안: `prototype/index.html` (브라우저에서 바로 열림). 화면 속 회사명·인물·수치는 모두 가상 데이터다.
- 미션 수행 화면은 **Microsoft 365 Copilot 채팅 창** 으로 표현한다: Copilot 호출 버튼 → "Microsoft 365 Copilot" 호출 화면 → Copilot 창(업무/웹 전환, 파일 첨부, 입력창 타이핑·전송, 말풍선, 작업 단계, 참조 출처, AI 생성 콘텐츠 안내) → 결과 문서에 "Copilot으로 작성됨" 표시.
- 공식 로고는 `prototype/assets/copilot-logo.svg`에 넣으면 모든 엠블럼이 자동 교체된다 (없으면 임시 엠블럼).
- **진행 방식 2종:** `클릭 진행`(기본, 발표·도슨트용)과 `자동 재생`(무인 키오스크용). 클릭 진행에서는 아래 순간에 재생이 멈추고 누를 곳만 밝게 강조된다. 해당 부분을 누르거나 Enter·→·프레젠터 리모컨으로 진행한다.
  1. Copilot 호출 버튼 → 2. 요청 전송 버튼 → 3~6. 처리 단계별 근거 위치 확인(4회) → 7~8. 사람 검토 표시(2회) → 9. 승인 도장
- **시작 화면 → 미션 선택:** 시작 화면의 START를 누르면 짧은 효과음과 함께 미션 카드 3장 화면으로 넘어가고, 본부 지령 음성(중저음)이 자막과 함께 재생된다. 대기 중에는 저음 앰비언트가 깔린다.
- **미션별 BGM (자체 작곡·실시간 합성):** 01 누아르 재즈(96BPM) / 02 긴박한 액션(138BPM, 시계 초침) / 03 잠입·소나(104BPM). 종료 후 시작 화면으로 돌아가면 페이드아웃된다. 녹음 음성·음원은 `prototype/assets/`에 넣으면 교체된다.
