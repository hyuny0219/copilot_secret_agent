## 0. Executive Summary

### 문제 정의
기존 AI 전시는 **"무엇을 만들었고 → 얼마나 좋아졌다"** 만 보여준다. 방문객이 궁금한 것은 그 사이의 **"어떻게"** 다.

```
  기존 AI 전시   [Agent 이름] ─────── ? ? ? ─────── [효과 30% ↑]
                              (방문객이 이해하지 못하는 구간)

  이번 부스      [문제] → [사용 데이터] → [Copilot 처리] → [결과물] → [효과]
                              (전부 화면에서 보여줌)
```

### 핵심 아이디어
**"Secret Agent의 비밀은 '능력'이 아니라 '수법'이다."**
진짜 기밀은 Agent의 이름이 아니라 **어떤 데이터를, 어떤 지시(프롬프트)로, 어떤 순서로 처리했는가** 이다. 부스는 이 수법을 "기밀 해제"하는 경험을 준다.

### 한 문장 컨셉
> 방문객은 **미션 카드 1장**을 뽑고, 실제 업무 화면에서 **Copilot을 불러 미션을 수행하는 과정**을 처음부터 끝까지 지켜본 뒤, 그 미션이 **실제 어느 부서의 어떤 사례였는지** 공개받는다.

### 권장안 요약
- 부스의 중심은 **Declassify Station**: 16:9 대형 화면에서 돌아가는 미션 카드형 프로그램.
- 실제 Copilot 계정·데이터 없이 **사전 제작 화면만으로 운영**한다 (라이선스·개인정보 문제 없음).
- 발표형(**클릭 진행**)과 무인형(**자동 재생**) 두 방식을 같은 프로그램으로 지원한다.

### 1-2. 세계관
- **AX 정보국 (AX Intelligence Agency, AXIA):** 회사 곳곳에서 반복 업무, 정보 과부하, 문서 작업이라는 "사건"을 해결해 온 비밀 조직. 지금까지의 작전 기록이 AX Day를 맞아 한시적으로 기밀 해제된다.
- **방문객 = 요원:** 본부의 지령을 받고 미션을 고르는 사람. 관람의 목적이 "구경"에서 **"우리 부서도 할 수 있나?"를 판단하는 것**으로 바뀐다.
- **Copilot = 현장 요원(Agent):** 업무 화면에서 호출되어 데이터를 읽고 결과물을 만든다. 마지막 판단은 언제나 사람이 한다.

| 미션 | 요원 코드네임 | 컬러 | 실제 부서 |
|---|---|---|---|
| 01 위장 잠입: 투자 심사역 | AGENT GOLD | 골드 | 투자운영파트 |
| 02 긴급 지령: 영국 이동 | AGENT BLUE | 블루 | 글로벌U/W기획 |
| 03 정보 확보: 해외 보험사 | AGENT RED | 레드 | 기획파트 |

**세계관 규칙 (콘텐츠 제작 원칙)**
1. **요원은 초능력자가 아니다.** 사람이 무엇을 시켰고 Copilot이 무엇을 읽었는지 반드시 보여준다.
2. **증거 없는 성과는 없다.** 효과 수치는 측정 기준과 함께 보여준다.
3. **최종 판단은 사람이 한다.** 모든 미션에 사람 검토 단계를 넣는다.
4. **마지막 장은 "당신의 부서"다.** 사례 공개 화면은 적용 가능 부서와 따라 쓸 프롬프트로 끝난다.

## 3. 활용사례 전시 방식 — 핵심

### 3-1. 원칙: 5단계를 화면 속 "작전"으로 보여준다
비즈니스 5단계를 텍스트 단락이 아니라 **업무 화면 위에서 실제로 일어나는 일**로 보여준다.

| 비즈니스 단계 | 화면에서 일어나는 일 | 방문객이 얻는 답 |
|---|---|---|
| ① 문제 | 미션별 실제 업무 화면(복잡한 자료함, 빈 품의서, 해외 홈페이지) + INCIDENT 요약 | "누가, 어떤 상황에서 괴로웠나" |
| ② 사용 데이터 | Copilot 창에 파일·메일·웹페이지가 첨부됨 | "Copilot이 **무엇을 읽었나**" |
| ③ Copilot 처리 | 프롬프트 입력·전송 → 작업 4단계 체크 → 업무 화면에서 근거 위치 강조 | "**어떻게 시켰고**, 어디서 근거를 찾았나" |
| ④ 결과물 | 결과 문서 생성 ("Copilot으로 작성됨"), 문장마다 출처 표기 | "**무엇이 만들어졌나**" |
| ⑤ 효과 | 사례 공개 화면의 Before/After 막대, 실제 부서 인용 | "**그래서 얼마나 나아졌나**" |

> 핵심 장치는 **근거 강조**다. 처리 단계마다 업무 화면의 어느 부분(재무제표의 번레이트 행, 메일의 출장 일정, 연차보고서 타일)을 읽었는지 노란 박스로 표시하고, 결과물의 문장마다 출처를 단다. "AI가 지어낸 것이 아니라 이 데이터에서 뽑았다"를 눈으로 보여준다.

### 3-2. "처리 과정(③)"을 보여주는 설계 — 블랙박스 열기

| 층 | 보여주는 것 | 화면 |
|---|---|---|
| 트리거 | 사람이 무엇을 했나 | 업무 화면의 Copilot 버튼을 누름 → "Microsoft 365 Copilot" 호출 화면 |
| 지시 | 정확히 어떤 문장으로 시켰나 | Copilot 입력창에 프롬프트가 타이핑되고 전송됨. 핵심 키워드 강조 |
| 참조 데이터 | Copilot이 읽은 것 | 첨부 파일 카드, 작업 단계별 근거 태그(E-01 IR p.4–18 등) |
| 사람 검토 | 사람이 어디를 고쳤나 | 결과 문서 위 빨간 펜 동그라미·메모, 승인 도장 |

> 사람 검토 단계는 빼지 않는다. "AI가 초안, 사람이 판단"을 보여줘야 현업이 "우리도 할 수 있다"고 믿는다.

> "글로벌 OO보험사의 실적 정보가 필요해요. 빠르게 확보할 수 있죠?"

| 단계 | 화면 |
|---|---|
| ① 문제 | 해외 보험사 IR 홈페이지. 연차보고서 312p, 실적 발표 64p, 영문·USD·IFRS 17 |

## 5. 참여감을 주는 연출

### 5-1. 설계 원칙: "조작은 최소로, 역할은 최대로"
- 방문객 조작은 **START 1번 + 카드 1장**이면 충분하다. 나머지는 도슨트의 클릭이나 자동 재생이 맡는다.
- 각 조작에 세계관 의미를 붙인다: START = 본부 접속, 카드 선택 = 미션 수락.

### 5-2. 클릭 진행 — 도슨트가 "작전을 지휘"하는 방식
아래 9곳에서 화면이 멈추고 누를 곳만 밝게 강조된다. 도슨트는 그 자리를 눌러 진행하며 설명한다. 프레젠터 리모컨(→, Enter, PageDown)도 쓸 수 있다.

| 순서 | 멈추는 순간 | 도슨트 멘트 예시 |
|---|---|---|
| 1 | Copilot 버튼 | "자, 이제 요원을 부르겠습니다." |
| 2 | 전송 버튼 | "지시는 이 한 문단이 전부입니다." |
| 3~6 | 근거 위치 4곳 | "Copilot이 지금 재무제표의 이 행을 읽었습니다." |
| 7~8 | 검토 표시 2곳 | "여기서 사람이 판단을 더합니다." |
| 9 | 승인 도장 | "최종 승인은 요원, 바로 사람입니다." |

### 5-3. 자동 재생 — 무인 셀프 관람
- 카드 1장만 고르면 약 90초 동안 같은 흐름이 자동으로 재생된다. 대기 인원이 많거나 도슨트가 없을 때 쓴다.

### 5-4. 소리 연출
| 장면 | 소리 |
|---|---|
| START | 묵직한 효과음 |
| 지령·미션 선택 | 본부 지령 음성(남성 중저음 녹음) + 오프닝 BGM(음성 중에는 작게) |
| 미션 01~03 | 미션별 첩보 액션 BGM |
| 엔딩 | 오프닝 곡을 다시 재생, MISSION COMPLETE |

## 7. 최종 권장안과 운영

### 7-1. 권장안
**Declassify Station 2대 운영 (메인 클릭 진행 1 + 셀프 자동 재생 1)**

| 이유 | 설명 |
|---|---|
| 5단계가 끊기지 않는다 | 문제 화면부터 데이터, 처리, 결과물, 효과까지 한 화면에서 이어서 보여준다 |
| "어떻게"에 정면으로 답한다 | 프롬프트 원문, 첨부 데이터, 근거 위치가 모두 화면에 나온다 |
| 운영 리스크가 낮다 | 실제 Copilot·계정·사내 데이터를 쓰지 않는다. 인터넷 없이 동작한다 |
| 발표와 셀프 관람을 같이 한다 | 같은 프로그램을 클릭 진행과 자동 재생으로 동시에 쓴다 |
| 행사 후에도 쓴다 | 사내 교육, 포털 소개 영상(화면 녹화)으로 재활용한다 |

### 7-2. 운영 인력
| 역할 | 인원 | 업무 |
|---|---|---|
| Handler (도슨트) | 1~2 | 메인 화면 클릭 진행과 설명, 질문 응대 |
| Desk Officer (선택) | 1 | 셀프 화면 안내, 사건 의뢰서 수거 |

### 7-3. 처리량
| 방식 | 1회 길이 | 시간당 회차 | 1회 관람 인원 |
|---|---|---|---|
| 메인 · 클릭 진행 | 2~3분 | 약 15~20회 | 8~12명 (함께 관람) |
| 셀프 · 자동 재생 | 약 1분 30초 | 약 30회 | 1~3명 |

### 7-4. 제작 일정 (행사 D-day 기준 예시)
| 기간 | 할 일 |
|---|---|
| D-28 ~ D-21 | 세 부서 사례 자료 수집(부록 8-1), 공개 범위 승인 |
| D-21 ~ D-14 | 시안에 실제 사례 반영, 글꼴 재생성, 브랜드·법무 확인 |
| D-14 ~ D-7 | 현장 PC·디스플레이로 테스트 (`PROGRAM_SPEC.md` 8-1 체크리스트), 도슨트 멘트 정리 |
| D-7 ~ D-1 | 리허설, 예비 PC 준비, 설치 |

### 7-5. 성공 지표
| 지표 | 측정 방법 |
|---|---|
| 미션 재생 횟수 | 운영자 집계 |
| 이해도 | 출구 1문항 스티커 투표 ("Copilot이 무엇을 읽고 어떻게 시켰는지 설명할 수 있다") |
| 적용 의향 | 사건 의뢰서 건수 · 지도 핀 수 (해당 공간을 만들 경우) |
| 행사 후 확산 | 의뢰 부서의 Copilot 활용 착수 여부 (AX 추진팀 후속 확인) |

### 7-6. 리스크와 결정이 필요한 것
| 항목 | 대응 |
|---|---|
| 사례 부서가 프롬프트 공개를 꺼림 | 고유명사를 뺀 공개용 프롬프트로 바꿈 (구조는 동일) |
| 효과 수치 과장 논란 | 측정 기준·기간을 함께 표시, 사람 검토 단계를 반드시 보여줌 |
| 현장 PC 고장 | 예비 PC에 같은 폴더를 복사해 두고 5분 안에 교체 |
| 미션 카드 선택 방식 | **결정 필요:** 화면 터치(현재) / 실물 버튼 3개 / 카드 RFID |
| 부스의 다른 공간 | **결정 필요:** Intelligence Map, Debrief Desk, 요원 ID 카드, 사건 의뢰서 제작 여부 |
| 브랜드·법무 | **확인 필요:** 삼성화재 명칭, 공식 Copilot 로고, 가상 회사명, 음원 라이선스(Pixabay) |
